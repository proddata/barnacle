# Hermit compatibility and production TODO

This tracks Hermit's API compatibility and production release gates. Compatibility was checked against `@neondatabase/serverless` 1.2.0 and Neon's SQL-over-HTTP/WebSocket implementation on 2026-10-03. A passing smoke test does not imply full protocol parity or production readiness.

## Working baseline

| Surface | Today | Evidence |
| --- | --- | --- |
| `POST /sql` single query | Parameterized query and Neon-shaped result | `integration/neon.test.mjs` |
| `POST /sql` batch | One transaction with an array of results | `integration/neon.test.mjs` |
| HTTP bearer header | OAUTHBEARER is required with Hermit's OIDC gate; without it, pgx can use OAUTHBEARER or legacy password authentication | `integration/neon.test.mjs`, `integration/oauth/run.mjs` |
| `GET /v2` and `/v1` WebSocket | Binary PostgreSQL wire tunnel; SCRAM login tested | `integration/neon.test.mjs`, `ws_test.go` |

| `GET /healthz` | Process liveness | `main.go` |
| Optional upstream routing | HTTP connection-string host and WebSocket `?address=` select an exact allowed address | `routing_test.go`, `integration/routing.mjs` |
| Upstream PostgreSQL TLS | Required by default for HTTP and WebSocket, with certificate and hostname verification; Compose generates a test CA | `pgtls_test.go`, `integration/pg-tls.mjs` |

## P0 — close gaps in the advertised API

- [x] **Accept the driver's batch isolation values.** `ReadUncommitted`, `ReadCommitted`, `RepeatableRead`, and `Serializable` all map to PostgreSQL transaction options and pass through `sql.transaction(..., { isolationLevel })` tests.
- [x] **Finish the parameter and type matrix.** The generated suite covers 55 built-in PostgreSQL type and parameter cases in both raw-text and plain-JSON modes; earlier integration cases cover custom enums, domains, composites, and ranges. A live comparison against a separately deployed Neon proxy matched 107 of 110 raw/plain variants, including result metadata. The three differences are in Neon's plain array conversion: two empty-array queries returned HTTP 500 and `box[]` was split at commas. Hermit preserves the PostgreSQL values. `integration/type-compare.mjs` reports these known differences and fails on new ones; the local Neon checkouts remain inspection-only.
- [x] **Match common result metadata and plain JSON conversion.** DDL reports `rowCount: null`; SELECT and INSERT counts, field metadata, duplicate names, array mode, `fullResults`, a custom type parser, and unusual scalar/array values have integration coverage. The generated type matrix compares metadata and both JSON modes with a deployed Neon proxy.
- [x] **Bound ordinary HTTP result memory.** Single queries stream, while the defaults cap HTTP concurrency at eight queries, raw row data at 8 MiB, buffered batch/custom-type data plus row overhead at 4 MiB, and uncompressed response JSON at 128 MiB. Size-limit regressions cover first-row, buffered-batch, and many-empty-row HTTP 413 responses. The historical 100 MiB comparison is in [benchmarks.md](benchmarks.md#100-mib-result-comparison).
- [x] **Handle huge fields before pgx materializes them.** Hermit configures pgx's PostgreSQL wire reader to reject oversized message bodies before allocation. With pgx 5.11, a 100 MiB single row returned HTTP 413 with a 13.4 MiB Hermit cgroup peak under the default policy, while 100 × 1 MiB still completed at 20.0 MiB. A limit reached after HTTP streaming begins still interrupts JSON rather than returning a clean 413.
- [x] **Prove OAuth/JWT with a real PostgreSQL validator.** The disposable PostgreSQL 18 suite uses [`pg_oauth_validator`](https://github.com/proddata/pg_oauth_validator), a local HTTPS issuer, a pinned audience and scope, and direct `appuser` identity mapping. A published Neon driver query succeeds with a signed JWT. Invalid signatures and audiences fail at Hermit's gate; wrong scope and requested role reach PostgreSQL and are rejected by its validator. The PostgreSQL 17 SCRAM Compose setup remains the ordinary developer suite. The pinned validator image build and end-to-end test passed in [GitHub CI](https://github.com/proddata/hermit/actions/runs/37137755634).
- [x] **Add an optional OIDC access-token gate before PostgreSQL.** Issuer and audience are pinned; discovery and JWKS are fetched over HTTPS, RS256 and `at+jwt` are required, and invalid HTTP bearer tokens or WebSocket cookies fail before dialing PostgreSQL. Tests cover key rotation, expiry, wrong issuer/audience, invalid signatures, and JWKS failure. PostgreSQL authentication remains separate.
- [x] **Map auth and SQL errors for the driver.** PostgreSQL auth failures now return HTTP 400 with SQLSTATE and Neon-shaped error fields; network failures return a generic 502. Integration covers wrong password, missing role/database, syntax and column errors, and a unique constraint violation. SCRAM intentionally returns `28P01` for both wrong passwords and missing roles.

## P1 — transport and operational confidence

- [x] **Support per-query `arrayMode` in request bodies.** Neon's SQL proxy accepts `arrayMode` on each query object, including single queries; Hermit now lets it override the request header. The published JavaScript driver sends `Neon-Array-Mode: true` and applies its own per-query `arrayMode` option after receiving results, so the integration suite checks both shapes.
- [x] **Exercise `Pool.query()` over HTTP.** The published driver runs `Pool.query()` through fetch with `poolQueryViaFetch=true`. Integration checks parameter binding, full result metadata, `rowMode: 'array'`, and the `viaNeonFetch` marker; the existing `Client`/WebSocket test remains.
- [x] **Verify cancellation.** Aborting a slow HTTP fetch stops the PostgreSQL query. A PostgreSQL CancelRequest crosses a second WebSocket connection and aborts a running query; an abrupt WebSocket disconnect makes Hermit send a bounded cancellation request using the captured backend key. Integration checks that the PostgreSQL session disappears promptly. Keep a database `statement_timeout` as a deployment policy for queries that outlive their clients during network partitions.
- [x] **Harden WebSocket shutdown and limits.** The relay streams fragmented and large frames, validates close payloads, answers ping, and releases the PostgreSQL session after a clean close. A 30 minute idle deadline closes silent or half-open sessions; 30 second per-write deadlines bound slow clients and PostgreSQL peers. Both are configurable. Go tests cover framing, deadlines, and the shared HTTP/WebSocket connection limit; the published driver runs a >64 KiB query and WSS ping/close tests through the deployment example.
- [x] **Decide whether to support client-initiated PostgreSQL TLS inside WebSocket.** Keep the verified Hermit-to-PostgreSQL TLS leg and the Neon driver's default `forceDisablePgSSL=true`. Client TLS inside the WebSocket would require a separate pass-through mode without Hermit's upstream certificate verification; the driver marks its pure-JS PostgreSQL TLS experimental. This is outside Hermit's current target.
- [x] **Add readiness and basic metrics.** `/readyz` can optionally check PostgreSQL TCP and TLS via `HERMIT_READY_PG_ADDR`, without database credentials. Opt-in `/metrics` reports active WebSockets, SQL request/error counts, and a request duration histogram. Stream interruption logs use fixed error kinds rather than raw errors; metrics contain no query text or credentials.
- [x] **Run end-to-end deployment checks.** HAProxy `https`/`wss`, Compose, Fedora integration and RPM installation, SIGTERM drain with active HTTP/WebSocket queries, and browser CORS/WebSocket-origin checks passed in [GitHub CI](https://github.com/proddata/hermit/actions/runs/37137755634).
- [x] **Decide whether HTTP connection reuse is needed.** Keep one upstream connection per HTTP request. In the [local connection-cost measurement](benchmarks.md#http-connection-reuse-decision), Hermit completed about 500 small HTTP queries per second at 6.7 ms p95 with eight in-flight slots. PgBouncer may pool PostgreSQL backends in deployment, reducing the reason for a Hermit-side pool. It would not eliminate Hermit-to-PgBouncer connection setup latency. Reconsider only after measuring the intended Fedora/PgBouncer setup; validate the OAuth path separately if PgBouncer is added.

## Production readiness — open gates

These checks apply to the actual release topology; they are separate from Neon API compatibility. Complete the relevant items before exposing Hermit to production traffic.

- [x] **Bound slow HTTP request bodies and idle connections.** `HERMIT_HTTP_READ_TIMEOUT` now bounds the whole HTTP request, including the body, at 15 seconds by default; `HERMIT_HTTP_IDLE_TIMEOUT` closes idle keep-alive connections after 60 seconds. Go clears HTTP deadlines on WebSocket hijack, leaving the separate WebSocket idle setting in control. The direct integration runner checks a slow incomplete body, an idle keep-alive connection, and a WebSocket that remains active past both HTTP deadlines.
- [ ] **Run the exact release commit through CI and an installed Fedora service.** All jobs passed on [commit `8a80fb3`](https://github.com/proddata/hermit/actions/runs/37138011162). CI builds, installs, smoke-tests, and verifies the RPM unit in a Fedora container. The local disposable systemd test exercised startup, a forced crash and restart, effective memory limits, sysconfig rotation with restart, and stop. Repeat these checks on the final release commit and a disposable Fedora host; exercise in-flight SIGTERM drain and certificate rotation there.
- [ ] **Lock down the production auth and network configuration.** Decide whether clients use SCRAM passwords or the OIDC/OAUTHBEARER path; for OAuth, configure the PostgreSQL validator, issuer, audience, scopes, and role mapping. Keep Hermit private behind the TLS ingress, disable the manual console, use a trusted upstream CA, and restrict `/metrics`. The included HAProxy example passes a canary check for sensitive headers in its logs; repeat that check on the production proxy/access logs for `Authorization`, `Neon-Connection-String`, and WebSocket auth cookies. Set PostgreSQL role privileges and `statement_timeout` for the intended workload.
- [ ] **Validate PgBouncer in the chosen topology if it is deployed.** Run the published Neon driver through Hermit and the selected PgBouncer pool mode for HTTP batches, WebSocket sessions, prepared statements, cancellation, TLS, and failures. PgBouncer authenticates clients itself; the tested PostgreSQL 18 OAuth path currently bypasses PgBouncer and must be proven separately before routing tokens through it.
- [ ] **Qualify the service on the target host and set alerts.** Run a representative load and soak test with realistic result sizes, concurrent WebSockets, slow clients, database restarts, and OIDC/JWKS outages. Record p95/p99 latency, PostgreSQL connections, Hermit RSS/cgroup peak, CPU, 503s, and recovery time. Tune the systemd memory limits and alert on errors, saturation, restarts, and readiness failures using the observed baseline.
- [ ] **Check release dependencies and rollback.** The local 2026-10-03 `govulncheck` scan found reachable advisories in Go 1.25.0 and `golang.org/x/text` 0.29.0; after updating to Go 1.25.14 and `x/text` 0.39.0 it found none. `npm audit` found no advisories. A local Trivy scan found four high-severity Alpine OpenSSL findings; upgrading the runtime packages cleared them, with zero high or critical findings in the rebuilt image. CI now reruns the Go, npm, and container scans. Audit the exact release container/RPM inputs and rehearse rolling back the RPM and ingress configuration before closing this gate.

## Deliberately outside the current target

Neon platform routing, compute wake-up, `Neon-Pool-Opt-In`, `Neon-Request-Id`, REST broker paths, console redirect auth, and multi-tenant endpoint management remain outside this target. Hermit's address allowlist is operator-configured and does not discover Neon endpoints. The serverless driver's default Neon URLs still need explicit `fetchEndpoint` and `wsProxy` overrides for Hermit.
